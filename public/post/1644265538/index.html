Grok Build被曝上传完整代码仓库，xAI回应数据留存争议 7月12日，安全研究团队 Cereblab 发布针对 Grok Build CLI 0.2.93 的网络流量分析。测试显示，在普通消费者账户下，Grok Build 会将完整的已跟踪 Git 仓库打包上传，其中包括代理未读取的文件和 Git 提交历史；被工具读取的 .env 测试文件内容也会未经脱敏地出现在模型请求及会话存档中。关闭“用于改进模型”选项后，相关仓库上传仍然发生。研究只能证明数据被传输和服务器接收，不能证明 xAI 将其用于模型训练，也不能证明所有账户均采用相同行为。 7月13日，研究者使用相同版本客户端再次进行了六次测试。新的服务器配置将代码库上传和追踪上传设为关闭，测试中未再出现 /v1/storage 仓库上传请求。这表明 xAI 可能已经通过服务器端配置进行了调整，但当时尚未公布调整范围、适用账户及此前数据的处理方式。 随后，xAI回应称，启用零数据留存（ZDR）的团队不会留存 Grok Build 的追踪和代码数据，通过 API Key 使用 Grok Build 时同样遵循 ZDR。未启用 ZDR 的用户可以在 CLI 中运行 /privacy，查看或关闭数据留存；关闭后，系统还会删除此前同步的数据。xAI官方文档确认 /privacy 可用于查看或切换隐私与数据留存状态，并表示团队级 ZDR 开启后，推理层不会持久保存提示词、代码或响应。 目前，xAI尚未在公开更新日志中详细说明此次事件涉及哪些版本和账户，也未公开此前上传数据的具体留存期限、删除流程及服务器端调整的完整覆盖范围。最新公开更新日志列出的版本为7月12日发布的 Grok Build 0.2.98。 X
