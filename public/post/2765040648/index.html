Surge的Tailscale 引擎重写 在之前的 Beta 版本中，Surge 的 Tailscale 实现基于官方实验性的 tailscale-rs 库。由于其功能集和性能未能完全满足 Surge 的需求，本次发布将其替换为直接内置于 Surge 网络引擎中的全新自主实现。新实现提供了更全面的功能、显著更高的性能以及更丰富的运行时诊断信息。 1. 现已支持直接点对点连接，包括 NAT 穿透和路径发现。Surge 会自动优先使用直连，在必要时回退到 DERP 中继。新增加的 derp-only 选项可强制所有对等流量通过 DERP。 2. 单线程数据平面吞吐量大幅提升，在实验室测试中可达到约 1.5 Gbps，与同等测试条件下的官方 Tailscale 客户端性能相当。 3. 新增出口节点（Exit Node）支持。现在可以通过 Tailscale 策略将 Surge 选定的流量路由至配置的出口节点，并作为普通出站策略使用。该功能仅影响 Surge 分配给此策略的流量，不会改变设备全局默认路由。 4. 支持授权 Tailscale 子网路由器通告的路由，MagicDNS 支持也得到进一步增强。 5. Surge 现在采用 Tailscale 感知的延迟测试机制。在未配置出口节点时，Surge 会针对在线对等节点进行原生的 Tailscale 连接探测；若无可用的合适对等节点，则测试本地 DERP 服务器。当配置了出口节点或 test-url 时，则使用标准的 HTTP 测试流程。同时为控制平面建立和初始 WireGuard 握手预留了额外的初始化时间。 6. 在 UI 中新增了大量 Tailscale 运行时诊断信息，包括：控制连接状态、分配的地址、出口节点状态、DERP 区域、直连/中继对等路径、对等节点延迟、活动连接、端点以及 MagicDNS 信息等。 7. 现有 Tailscale 配置档案和已持久化的节点身份保持完全兼容，无需进行档案迁移。 我们计划在未来版本中加入 WireGuard 和 Tailscale 的入站访问功能，允许远程设备连接到 Surge 并将其用作网络网关。 注意：由于核心引擎更换，Tailscale 需要重新注册。若之前未启用 auth key 的复用选项，则必须生成新的 auth key 来完成新的设备注册流程。 标签:#surge Created by RocM 官方频道:@rocCHL 官方群组:@roctech 官方合作:@rocmmbot
