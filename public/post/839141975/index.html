Есть безобидные промпт-инъекции, которыми "детишки" балуются, когда хотят…

Есть безобидные промпт-инъекции, которыми "детишки" балуются, когда хотят обойти HR-фильтры ☝️ А есть и более интересные истории. Тут один норвежский исследователь, Хокон Молёй (Håkon Måløy), обнаружил способ внедрить в документ Word скрытый промпт. Он маскируется, например, белым текстом на белом фоне или другим невидимым форматированием, поэтому пользователь его не замечает. Однако Copilot перед обработкой документа удаляет форматирование и передает модели чистый текст. В результате скрытая инструкция становится видимой для LLM и воспринимается как команда. Самая интересная часть исследования заключается не в самом prompt injection. Исследователь добавил вторую инструкцию: 📎 изменить создаваемый документ (в демонстрации — уменьшить все финансовые показатели вдвое) 📎 после этого встроить тот же скрытый промпт в новый документ, который создаст Copilot. Получается цепочка: 6️⃣ злоумышленник отправляет зараженный Word-файл 2️⃣ сотрудник использует его вместе с Copilot 3️⃣ Copilot выполняет скрытые инструкции 4️⃣ Copilot автоматически добавляет тот же скрытый промпт в новый документ 5️⃣ этот документ отправляется коллегам 6️⃣ их Copilot тоже оказывается "заражен". Именно способность к самораспространению делает атаку похожей на компьютерного червя. Автор отмечают два сценария: ➡️ пользователь вручную прикрепляет документ к Copilot ➡️ Copilot сам ищет документы в OneDrive (режим Work IQ) и находит зараженный файл. Во втором случае пользователь может даже не подозревать, что вредоносный документ вообще использовался при подготовке ответа. Исследователь сообщил об ошибке в Microsoft еще весной 2026 года. За несколько месяцев Microsoft выпустила несколько вариантов защиты: ➡️ изменила интерфейс Copilot ➡️ доработала фильтрацию ➡️ обновила модель до GPT-5.5. Каждый раз исследователь находил способ обойти защиту и воспроизвести атаку другими формулировками. В итоге Microsoft признала, что речь идет не о единичной ошибке, а о более фундаментальной проблеме архитектуры LLM. Чтобы определить, является ли документ вредоносным, модель должна его сначала прочитать. Но как только она его прочитала, вредоносный промпт уже попал в контекст модели и может повлиять на дальнейшее рассуждение. Раньше мы говорили о prompt injection, когда злоумышленник заставляет модель выполнить нежелательное действие. Теперь показано, что prompt injection может стать самораспространяющимся. То есть появляется аналог классических сетевых червей, только распространяются уже не исполняемые файлы, а инструкции для LLM, которые незаметно переносятся из одного ИИ-обрабатываемого документа в другой. Это качественно новый класс угроз для корпоративных ИИ-помощников, особенно тех, которые автоматически читают документы, почту, OneDrive, SharePoint и другие внутренние источники данных 🪱 #ии #malware
